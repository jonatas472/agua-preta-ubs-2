# Relatório de execução — P4: Cadastro

**Projeto:** Água Preta UBS  
**Data:** 27/10/2026  
**Escopo:** entidade Cadastro e integração local com Room  
**Branch de trabalho:** `feature/cadastro-entity`

## 1. Resumo

Foi preparada a persistência local da entidade `Cadastro` com Room. O trabalho configura o processamento das anotações Room por KSP, disponibiliza operações de inserção e listagem, cria o banco de dados e um ViewModel que encaminha gravações e publica o resultado para uma interface futura.

Não foi criada tela nova nem conectada a tela de Perfil, que continua apresentando dados demonstrativos. Também não foi implementada comunicação Retrofit: o PRD principal marca Room como persistência e não define API ou endpoint.

## 2. Análise do PRD e decisão sobre a entidade

O PRD principal na raiz do repositório, referenciado pelo README, define a entidade `Cadastro` com:

| Campo | Tipo | Regra |
|---|---|---|
| `id` | `Int` | Chave primária autogerada |
| `nome` | `String` | Obrigatório |
| `cartaoSUS` | `String` | Obrigatório |
| `dataNascimento` | `String` | Obrigatório |
| `telefone` | `String` | Obrigatório |

O plano inicial mencionava `Long` para o identificador, mas o PRD principal e a entidade já existente no código especificam `Int`. Foi mantida a definição existente, sem duplicar ou renomear a classe como `CadastroEntity`.

O arquivo `docs/PRD.md` não define os campos de Cadastro; ele contém uma especificação de Agendamento. Por isso, para esta tarefa, foi usada a definição explícita de Cadastro do `PRD.md` principal.

## 3. Implementação

### Entidade existente

`src/app/src/main/java/br/edu/ifpe/ubsaude/Data.kt` já contém a `data class Cadastro` anotada com `@Entity`, chave `@PrimaryKey(autoGenerate = true)` e os cinco campos acima. O arquivo não precisou ser alterado.

### DAO

Foi criado `src/app/src/main/java/br/edu/ifpe/ubsaude/CadastroDao.kt` com:

- `inserir(cadastro)`: operação `suspend` anotada com `@Insert`, que retorna o identificador gerado pelo Room.
- `listar()`: consulta `SELECT * FROM Cadastro ORDER BY nome ASC`, observada por `Flow<List<Cadastro>>` para que os consumidores possam receber atualizações da lista.

Não foram adicionadas operações de atualização ou exclusão, pois o PRD não as exige.

### Banco Room

Foi criado `src/app/src/main/java/br/edu/ifpe/ubsaude/AppDatabase.kt`:

- registra somente `Cadastro` nesta etapa;
- usa versão inicial `1`, sem migração, pois o projeto ainda não tinha um banco configurado;
- disponibiliza `cadastroDao()` e uma instância reutilizável de `AppDatabase`;
- cria o arquivo local `ubs_database` usando o contexto da aplicação.

As outras entidades que já existem no projeto não foram registradas nem modificadas nesta tarefa.

### ViewModel

Foi criado `src/app/src/main/java/br/edu/ifpe/ubsaude/CadastroViewModel.kt`:

- recebe `CadastroDao`;
- expõe `cadastros` como `Flow<List<Cadastro>>`;
- executa `salvar(cadastro)` em `viewModelScope`;
- publica uma mensagem de sucesso ou, diante de `SQLiteException`, registra a falha no log e publica a mensagem amigável definida no PRD: “Não foi possível salvar. Tente novamente.”

O ViewModel está preparado para ser usado pela interface, mas ainda não é instanciado pelo fluxo Compose. A tela de Perfil permanece demonstrativa e não há uma tela de Cadastro no fluxo atual.

### Processamento Room e KSP

Foram feitas as seguintes mudanças de configuração, sem atualizar as versões existentes de Kotlin, Room, AGP ou Gradle:

- `src/gradle/libs.versions.toml`: alias do plugin KSP (`2.2.10-2.0.2`) e do compilador Room (`2.8.5`);
- `src/build.gradle.kts`: declaração do plugin KSP;
- `src/app/build.gradle.kts`: aplicação do KSP e inclusão de `ksp(libs.androidx.room.compiler)`;
- `src/gradle.properties`: configuração `android.disallowKotlinSourceSets=false`, necessária para o KSP com o AGP 9.1.1 e o Kotlin embutido.

Essa última configuração é experimental no AGP e gera um aviso durante a compilação. Ela foi adicionada após a primeira tentativa de build informar que o AGP bloqueava as fontes geradas pelo KSP sem essa opção.

- **`assembleDebug`: passou.** Foi executado a partir de `src` com `ANDROID_HOME` apontando para o SDK Android instalado. O KSP gerou `AppDatabase_Impl.kt` e `CadastroDao_Impl.kt`, e as etapas `kspDebugKotlin` e `compileDebugKotlin` finalizaram com sucesso.
- **`testDebugUnitTest`: passou.** Resultado: 1 teste executado, 0 falhas e 0 erros. O único teste existente é o teste de exemplo de soma; não há teste específico de Cadastro no projeto.
- **`git diff --check`: passou**, sem erros de whitespace.
- **Revisão de escopo:** não foram alteradas a tela Compose, as outras entidades, Retrofit, autenticação ou sincronização.

Na primeira tentativa de compilação, o AGP bloqueou as fontes geradas pelo KSP; após aplicar a configuração indicada pela mensagem do build, a compilação prosseguiu. Em seguida foi necessário definir `ANDROID_HOME` no comando porque a variável não estava configurada no ambiente. Não foi criado `local.properties`.
