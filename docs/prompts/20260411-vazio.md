# Planejamento de IA — Estado Vazio (Empty)

**Projeto:** Água Preta UBS  
**Responsável:** Cecília Helena  
**Branch:** `feature/estados-da-tela`

## 1. Objetivo

Implementar o estado Vazio da tela principal do Água Preta UBS.

Esse estado deverá aparecer quando uma operação for concluída corretamente, mas não existirem dados para apresentar ao usuário.

A interface deverá informar que não há registros disponíveis, sem transmitir a impressão de que ocorreu algum erro.

## 2. Investigação inicial

Antes de modificar qualquer arquivo:

- Ler AGENTS.md e PRD.
- Analisar a tela principal.
- Identificar quais informações são apresentadas nela.
- Verificar como os dados são consultados.
- Localizar o ViewModel e o UiState compartilhado.
- Verificar como o aplicativo identifica uma consulta sem resultados.
- Conferir as alterações pendentes no Git.

Não presumir que o aplicativo ainda não possui uma implementação de estado vazio.

## 3. Implementação visual

Criar o componente do estado Vazio utilizando Jetpack Compose.

A interface deverá:

- Apresentar uma mensagem informando que não existem dados disponíveis.
- Utilizar uma composição visual simples e coerente com o aplicativo.
- Manter a identidade visual do Água Preta UBS.
- Evitar apresentar mensagens que indiquem falha quando a consulta foi bem-sucedida.
- Adaptar-se ao espaço disponível na tela.

Não criar uma tela completamente diferente da identidade visual existente.

## 4. Integração com UiState

Utilizar o UiState compartilhado criado por Jonatas.

Não criar outra classe UiState, sealed class ou ViewModel independente.

O componente deverá ser apresentado quando a consulta retornar corretamente, mas sem registros.

A lógica que identifica a ausência de dados deverá permanecer na camada apropriada, respeitando a arquitetura existente.

## 5. Textos

Adicionar os textos necessários ao arquivo `strings.xml`.

Sugestão de mensagem:

"Não há informações disponíveis no momento."

Ajustar a mensagem conforme o contexto real da tela principal.

Não deixar textos fixos diretamente nos componentes Compose.

## 6. Critérios de aceitação

- [ ] O estado Vazio aparece quando não existem registros.
- [ ] O estado não aparece quando ocorre uma falha.
- [ ] A mensagem é compreensível.
- [ ] A interface mantém a identidade visual.
- [ ] Os textos estão em strings.xml.
- [ ] O componente funciona com o UiState compartilhado.
- [ ] Não existem dados fictícios apresentados como reais.

## 7. Testes

Utilizar uma fonte de dados vazia ou uma situação controlada para verificar o comportamento.

Confirmar que:

- A consulta termina sem erro.
- O estado Vazio aparece.
- O aplicativo continua funcionando.
- Quando existirem dados, a tela poderá apresentar Sucesso.

Registrar o resultado real dos testes.

## 8. Documentação

Registrar a implementação em `docs/outputs/`, informando os arquivos modificados e os testes realizados.
